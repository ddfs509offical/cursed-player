# Режим экономии (читать перед каждой задачей)

Факты по проекту: 350 млн токенов за ~3 суток стоили $3.52 (99% — попадание в кеш).
Значит расход определяет не «сложность», а объём перечитанного кода и число параллельных агентов.
Правила ниже обязательны по умолчанию; отступать от них — только по прямой просьбе владельца.

## 1. Работать самому, а не звать подрядчиков

- **По умолчанию задачу делает основной агент.** Подрядчик (subagent) — только если задача
  реально независимая И большая (переписать страницу, сделать новую подсистему).
- **Не больше одного подрядчика одновременно.** Три параллельных агента = трёхкратное
  перечитывание одних и тех же файлов = трёхкратный расход.
- Не дробить мелочи на подрядчиков: правка на 5 строк делается в основном потоке.

## 2. Не перечитывать то, что уже известно

- Перед чтением файла — поиск по имени/символу (`grep`), а не чтение целиком.
- Читать **окнами** (`offset`/`limit`), а не файл на 1000 строк.
- Если файл менялся в этой же сессии — не читать заново, править по известному фрагменту.
- Держать карту проекта в `PROJECT_MAP.md` (см. ниже) и обновлять её, а не держать в голове.

## 3. Правки — точечные

- `edit` с уникальным фрагментом вместо `write` целого файла.
- Не переписывать файл ради переименования переменной.
- Не добавлять «на будущее» код, который никем не используется.

## 4. Вывод команд — фильтровать

- `cargo test` — только строки `test result`, ошибки; не весь вывод.
- Сборки — `Select-Object -Last 1`, а не потоки логов.
- Не печатать дампы DOM целиком: 3–5 ключевых полей.
- Скриншоты — только когда вопрос про внешний вид; в остальных случаях текстовые проверки.

## 5. Не проверять дважды

- Проверка нужна один раз на изменение. Если уже проверено и не менялось — не повторять.
- «Проверь всё заново» — только по прямой просьбе.
- Сборка exe, тесты и запуск приложения **бесплатны** (тратят время, не деньги) — на них экономить не надо.

## 6. Пакетная работа

- Собирать пожелания владельца в один заход: пять правок в одном цикле дешевле пяти циклов.
- В конце партии — одна сборка и один прогон проверок.

## 7. Отчётность

В конце каждой партии писать одну строку:
`расход: подрядчиков N · правок M · примерный объём (мало/средне/много)`.
Это позволяет владельцу видеть трату без открытия кабинета.

## 8. Когда экономия не применяется

- Безопасность (ключи, RLS, утечки) — проверять тщательно, сколько бы ни стоило.
- Данные пользователя (миграции, синхронизация, удаления) — не экономить на проверке.
- Явная просьба владельца «сделай как следует, не жалей токенов».
